# 機能定義書 F04: コメント

**関連:** 要件 [04_features.md](../04_features.md) 5.5 / ユースケース [03_usecases.md](../03_usecases.md) UC-07・UC-08 / 画面 [06_ui_design.md](../06_ui_design.md) SCR-04 / データ [07_er_diagram.md](../07_er_diagram.md) `comments`

## 1. 概要 / 目的
投稿に対してコメント（返信）を付けられるようにする。第三者のコメントを想定し、投稿ごとのコメント数を可視化する。

## 2. 機能詳細
- 投稿詳細画面（SCR-04）でコメントを作成できる
- コメントは**古い順**（`id` の昇順）で一覧表示し、カーソルページング（無限スクロール）で読み進める
  - 会話は上から下へ読むものなので、後から来たコメントで既読部分の位置がずれない古い順に統一する
- コメント作成でその投稿のコメント数が +1、削除で −1 される
- 自分のコメントのみ編集・削除できる
  - X ではリプライもポストの一種で編集可否が投稿と同じなので、投稿（F03）と揃えて編集も可とする
- コメント投稿者名クリックでプロフィール（SCR-05）へ遷移

## 3. 対象画面
- SCR-04 投稿詳細画面（コメント一覧・入力フォーム）

## 4. API エンドポイント案

| メソッド | パス | 説明 | 認証 |
|----------|------|------|------|
| GET | `/api/posts/{postId}/comments` | 投稿のコメント一覧取得（`cursor` / `limit`） | 要 |
| POST | `/api/posts/{postId}/comments` | コメント作成（body） | 要 |
| PUT | `/api/comments/{id}` | コメント編集（本人のみ） | 要 |
| DELETE | `/api/comments/{id}` | コメント削除（本人のみ） | 要 |

一覧のレスポンス：`{ comments: [...], nextCursor }`。`cursor` には前回の `nextCursor` をそのまま渡す。古い順なので、続きは「そのカーソルより**新しい**コメント」になる。

コメント要素：`id, postId, body, author{id, username, displayName}, createdAt, updatedAt`

## 5. データ
- `comments`（id, post_id, user_id, body, created_at, updated_at）
- コメント数：`comments` を `post_id` で `COUNT`（非正規化カウンタは持たない。07_er_diagram.md 8.4）
- インデックス `idx_comments_post_id (post_id, id)` が一覧の絞り込み・並び替えとコメント数の `COUNT` を兼ねる
- コメント数はタイムラインの投稿ごとに必要になるが、投稿を取得する SQL の中で一緒に集計する（N+1 を作らない）

## 6. バリデーション / 制約
- 本文：必須・最大 500 文字（`comments.body` の `VARCHAR(500)` に合わせる）
- 認可：編集・削除はコメント所有者のみ
- 対象投稿が存在すること

## 7. エラーハンドリング / 異常系
- 空/文字数超過：エラー表示（400・`fieldErrors.body`）
- 他人のコメント編集・削除要求：403
- 存在しない投稿へのコメント / 存在しないコメントの編集・削除：404
  - 存在確認（404）を認可（403）より先に行う。逆にすると「その id のコメントが他人のものとして存在する」ことが漏れる
