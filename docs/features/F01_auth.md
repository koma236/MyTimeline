# 機能定義書 F01: 認証（サインアップ / ログイン / ログアウト）

**関連:** 要件 [04_features.md](../04_features.md) 5.2 / ユースケース [03_usecases.md](../03_usecases.md) UC-01〜03 / 画面 [06_ui_design.md](../06_ui_design.md) SCR-01・SCR-02 / データ [07_er_diagram.md](../07_er_diagram.md) `users`

## 1. 概要 / 目的
複数ユーザーの利用を前提に、アカウント登録・ログイン・ログアウトを提供する。認証が必要な操作を保護し、投稿・コメント・いいね・フォローを本人の操作として記録できるようにする。

## 2. 機能詳細
- **新規登録:** username・表示名・メール・パスワードを入力してアカウントを作成し、そのままログイン状態にする
- **ログイン:** メール（または username）＋パスワードで認証し、認証情報（トークン/セッション）を発行する
- **ログアウト:** 認証情報を破棄し、ログイン画面へ戻す
- 未ログイン状態で認証必須画面にアクセスした場合はログイン画面へリダイレクトする

### 認証方式（[08_constraints.md](../08_constraints.md) TBD-01 決定事項）

**アクセストークン（JWT）＋ リフレッシュトークン（DB 管理）の 2 トークン方式**を採用する。

#### アクセストークン

- 実体は **JWT（HMAC-SHA 署名）**。署名アルゴリズムは署名鍵の長さから決まる（32 / 48 / 64 バイト以上でそれぞれ HS256 / HS384 / HS512）
- クライアントは `Authorization: Bearer <accessToken>` で送信する
- サーバーはセッションを保持せず、リクエストごとに署名と有効期限だけを検証する
- 有効期限は既定 **15 分**（`JWT_ACCESS_EXPIRATION_MINUTES`）。失効させられない代わりに短命にすることで、漏れた場合の被害を限定する
- 含めるのは userId・username・発行時刻・有効期限のみ。パスワードなどの秘密情報は含めない
- **クライアントはメモリにのみ保持し、localStorage に保存しない**（XSS で読み出されないようにするため）

#### リフレッシュトークン

- 実体は **`SecureRandom` による 256bit の不透明なランダム値**。JWT ではない。DB 照合が前提なので署名で自己完結させる意味がないため
- **httpOnly Cookie** で往復させる。属性は `HttpOnly; SameSite=Lax; Path=/api/auth; Max-Age=14日`。JavaScript から読めないため XSS でも持ち出されない
  - `Secure` 属性は `REFRESH_COOKIE_SECURE` で切り替える。HTTPS の本番では必ず `true` にすること
  - `Path=/api/auth` により、投稿 API など他のエンドポイントには送信されない
- 有効期限は既定 **14 日**（`JWT_REFRESH_EXPIRATION_DAYS`）
- DB（`refresh_tokens`）には**生値ではなく SHA-256 ハッシュを保存する**。パスワードと同じく、DB が漏れてもそのままセッションを乗っ取られないようにするため
- **使用するたびにローテーションする。** 1 回使ったトークンは失効させ、新しいトークンを発行して Cookie を差し替える

#### 失効とローテーション

- **ログアウトはサーバー側でリフレッシュトークンを失効させる**（そのユーザーの全セッションを失効）。アクセストークンは短命なため、最大 15 分だけ有効なまま残る
  - `POST /api/auth/logout` は**認証不要**。アクセストークンが期限切れの状態でもログアウトできる必要があるため、Cookie のリフレッシュトークンで本人を特定する
  - トークンが無効・不在でも常に 204 と削除用 Cookie を返す。成否を返すとトークンの存在有無を推測できてしまうため
- **失効済みトークンの再提示は盗用とみなす。** 正規の利用者は必ず最新のトークンを持っているため、古いトークンが出てきた時点でどちらが正規か判別できない。そのため**そのユーザーの全セッションを失効させる**
  - この失効処理は、直後に投げる 401 例外でロールバックされないよう**独立したトランザクション**（`REQUIRES_NEW`）で実行する

#### クライアント側の挙動

- 起動時に `POST /api/auth/refresh` を 1 回呼び、成功すればログイン状態を復元する（アクセストークンはメモリのみなのでリロードで消えるため、これが唯一の復元手段）
- 保護 API が 401 を返したら自動的に `refresh` してから元のリクエストを 1 度だけ再送する
- **並行する複数の 401 は 1 本の refresh にまとめること。** 同時に複数の refresh を投げると 2 本目が使用済みトークンを提示し、盗用検知によって正規の利用者が強制ログアウトされてしまう

## 4. API エンドポイント案

| メソッド | パス | 説明 | 認証 |
|----------|------|------|------|
| POST | `/api/auth/signup` | 新規登録（username, displayName, email, password） | 不要 |
| POST | `/api/auth/login` | ログイン（identifier, password）→ トークン発行 | 不要 |
| POST | `/api/auth/refresh` | アクセストークンの再発行（Cookie で認証） | 不要（Cookie） |
| POST | `/api/auth/logout` | ログアウト（リフレッシュトークンを失効） | 不要（Cookie） |
| GET | `/api/auth/me` | ログイン中ユーザー情報の取得 | 要 |

`signup` / `login` / `refresh` はいずれも同じ形式を返す。リフレッシュトークンは Cookie で返るためボディには含まれない。

```json
{ "accessToken": "<JWT>", "user": { "id": 1, "username": "taro", "displayName": "山田太郎", "email": "taro@example.com", "bio": null, "createdAt": "2026-07-27T12:34:56.789" } }
```

## 5. データ
- `users`（id, username〔UNIQUE〕, display_name, email〔UNIQUE〕, password_hash, bio, created_at, updated_at）
- `refresh_tokens`（id, user_id, token_hash〔UNIQUE〕, expires_at, revoked_at, created_at）— 1 行が 1 セッションに対応する
- パスワードは **BCrypt でハッシュ化して `password_hash` に保存**（平文保存しない）
- リフレッシュトークンは **SHA-256 でハッシュ化して `token_hash` に保存**（生値は保存しない）
- ログインの入力欄はメールアドレスとユーザー名を兼ねるため、email → username の順で該当ユーザーを探す

## 6. バリデーション / 制約
- username：必須・UNIQUE・半角英数字/アンダースコア・長さ制限（例: 3〜50 文字）
- display_name：必須・長さ制限（例: 1〜100 文字）
- email：必須・メール形式・UNIQUE
- password：必須・最小長（例: 8 文字以上）
- Spring Security ＋ Bean Validation で検証

## 7. エラーハンドリング / 異常系
- username / email 重複：409 相当のエラーを項目単位で表示
- 認証失敗（ログイン）：「メールアドレスまたはパスワードが正しくありません」を表示（どちらが誤りかは明示しない）
- バリデーションエラー：該当項目にエラーメッセージを表示
- 認証切れ / 未ログインで保護 API を呼んだ場合：401 を返しログイン画面へ誘導

### エラーレスポンス形式

項目単位の表示ができるよう、すべてのエラーを共通形式で返す。

```json
{ "message": "入力内容を確認してください", "fieldErrors": { "email": "このメールアドレスは既に登録されています" } }
```

| ケース | ステータス | 内容 |
|--------|-----------|------|
| バリデーション NG | 400 | `fieldErrors` に項目ごとのメッセージ |
| username / email 重複 | 409 | `fieldErrors` に該当項目 |
| ログイン失敗 | 401 | `message` のみ（ユーザー不在とパスワード誤りを区別しない） |
| 未認証で保護 API を呼び出し | 401 | `message` のみ（`ログインが必要です`） |
| リフレッシュトークンが無効 / 期限切れ / 失効済み | 401 | `message` のみ（`セッションの有効期限が切れました。再度ログインしてください`）。理由は区別しない |
