# 機能定義書 F03: 投稿・画像投稿（S3）

**関連:** 要件 [04_features.md](../04_features.md) 5.4 / ユースケース [03_usecases.md](../03_usecases.md) UC-05・UC-06 / 画面 [06_ui_design.md](../06_ui_design.md) SCR-03・SCR-04 / データ [07_er_diagram.md](../07_er_diagram.md) `posts`・`post_images` / インフラ [09_infrastructure.md](../09_infrastructure.md)

## 1. 概要 / 目的
テキスト（＋画像）による投稿を作成・削除する。画像は AWS S3 に保存し、DB には `s3_key` のみを記録する。

## 2. 機能詳細
- **投稿作成:** 本文を入力し、必要に応じて画像（最大 4 枚）を添付して投稿する
- 投稿はタイムラインの先頭（新しい順）に反映される
- **投稿編集:** 自分の投稿の本文のみ編集できる。画像の差し替え・追加・削除はできない
- **投稿削除:** 自分の投稿のみ削除できる。削除時は配下の画像・コメント・いいねもカスケード削除する（DB は外部キーの CASCADE、S3 の画像本体はアプリが削除）
- **画像アップロードフロー:**
  1. クライアントは投稿作成 API に本文と画像ファイルを multipart で送る
  2. サーバーが画像を検証（実フォーマット・サイズ・寸法・枚数）して S3 に保存し、採番したキーを `post_images` に記録する

> 当初案の pre-signed URL による直接アップロードは採用していない。サーバーを経由しないと
> 実フォーマットの検証（`ImageValidator`）を通せず、画像でないファイルを画像として
> 配信されうるため。プロフィール画像（F07）と同じ方式に揃えている。

## 3. 対象画面
- SCR-03 タイムライン画面（投稿フォーム）
- SCR-04 投稿詳細画面（投稿本体・削除メニュー）

## 4. API エンドポイント

| メソッド | パス | 説明 | 認証 |
|----------|------|------|------|
| POST | `/api/posts` | 投稿作成（multipart: `body`, `images`×0〜4） | 要 |
| GET | `/api/posts/{id}` | 投稿詳細取得 | 要 |
| PUT | `/api/posts/{id}` | 投稿編集（JSON: `body`。本人のみ） | 要 |
| DELETE | `/api/posts/{id}` | 投稿削除（本人のみ） | 要 |

- 作成は画像なしでも multipart で送る（JSON と multipart の 2 経路を持たない）
- レスポンスの投稿要素には `imageUrls[]`（表示順・期限付きの署名付き URL）が入る

## 5. データ
- `posts`（id, user_id, body, created_at, updated_at）
- `post_images`（id, post_id, s3_key, position, created_at）。`position`（0〜3）が表示順
- 画像本体は S3（画像バケット）に保存。キーは `posts/{userId}/{UUID}.{拡張子}` で採番し、ファイル名にユーザーの入力を使わない（F07 と同じ方針）
- 閲覧は期限付きの署名付き URL を都度発行する（バケットは公開しない）

## 6. バリデーション / 制約
- 本文：最大 280 文字（[08_constraints.md](../08_constraints.md) TBD-04）。**本文が空かつ画像も無い場合は投稿不可**（編集で本文を空にできるのも画像付きの投稿だけ）
- 画像：最大 4 枚。形式は JPEG / PNG、1 枚あたり 2MB・縦横 4096px 以内（TBD-05）。判定は申告された Content-Type ではなくバイト列の実フォーマットで行う
- 認可：編集・削除は投稿の所有者のみ（他人の投稿は操作メニュー非表示＋API でも 403）

## 7. エラーハンドリング / 異常系
- 文字数超過・形式不正・枚数超過・サイズ超過：400（画像の拒否理由は `fieldErrors.image`）
- 本文が空かつ画像も無い：400
- S3 への保存失敗：500。保存済みの画像は片付け、投稿自体を作らない（クライアントはそのまま再送すればよい）
- 他人の投稿の編集・削除要求：403
- 存在しない投稿の取得/編集/削除：404
