# 機能定義書 F02: タイムライン（2 タブ）

**関連:** 要件 [04_features.md](../04_features.md) 5.3 / ユースケース [03_usecases.md](../03_usecases.md) UC-04 / 画面 [06_ui_design.md](../06_ui_design.md) SCR-03 / データ [07_er_diagram.md](../07_er_diagram.md) `posts`・`follows`・`likes`・`comments`

## 1. 概要 / 目的
投稿を新しい順に一覧表示するメイン画面。「すべて」「フォロー中」の 2 タブで、全体からの発見とフォロー関係に応じた閲覧の両方を提供する。

## 2. 機能詳細
- **すべてタブ（左・デフォルト）:** 全ユーザーの投稿を新しい順に表示（発見用）。フォローが 0 人の初回ログイン直後でも投稿が見えるよう、初期選択とする
- **フォロー中タブ（右）:** 自分＋自分がフォローしているユーザーの投稿を新しい順に表示
- 各投稿カードに、投稿者（表示名 / @username）・投稿日時・本文・画像・**いいね数**・**コメント数**を表示
- 投稿者名クリックでプロフィール（SCR-05）へ遷移
- いいねボタン・コメント数からそれぞれ F05・F04（投稿詳細）へ接続
- 件数の多いタイムラインに備え、ページング（無限スクロール / カーソルベース）で取得

## 3. 対象画面
- SCR-03 タイムライン画面（メイン）

## 4. API エンドポイント案

| メソッド | パス | 説明 | 認証 |
|----------|------|------|------|
| GET | `/api/timeline/following?cursor=&limit=` | フォロー中タイムライン（自分＋フォロー先） | 要 |
| GET | `/api/timeline/all?cursor=&limit=` | 全体タイムライン | 要 |

**レスポンス（投稿要素）例:** `id, body, image_urls[], author{id, username, display_name}, like_count, comment_count, liked_by_me, created_at`

## 5. データ
- 投稿本体：`posts`、画像：`post_images`、投稿者：`users`
- フォロー中タブの対象 user_id：`follows`（follower_id = 自分）＋ 自分自身
- `like_count` / `comment_count`：`likes` / `comments` の `COUNT`
- `liked_by_me`：ログインユーザーの `likes` 有無

## 6. バリデーション / 制約
- `limit` は上限値を設ける（例: 最大 50）
- 未認証は 401
- フォロー中タブが 0 件の場合、ユーザー検索（SCR-06）への導線を表示

## 7. エラーハンドリング / 異常系
- 取得失敗時はエラーメッセージ＋再読み込み導線を表示
- カーソル不正時は先頭から取得し直す
